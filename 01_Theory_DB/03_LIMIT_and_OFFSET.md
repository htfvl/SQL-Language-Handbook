# ─── 🎚️ 02_FILTERING_DATA / ОГРАНИЧЕНИЯ И ФИЛЬТРАЦИЯ СТРОК ───

Из базовой теории выборок мы узнали, как извлекать определенные столбцы. Однако если таблица содержит огромное количество строк, читать и обрабатывать весь массив данных силами бэкенда неэффективно и ресурсоемко. 

Для фильтрации результатов и отсечения ненужных записей используется конструкция **`WHERE`**. Этот оператор применяется индивидуально к каждой строке данных в таблице: СУБД проверяет значения указанных столбцов на соответствие заданному условию и решает, включать ли строку в финальный результат.

### 📑 АРХИТЕКТУРА ЗАПРОСА С ФИЛЬТРАЦИЕЙ:
```sql
SELECT column1, column2 FROM table_name WHERE (условие_1) AND/OR (условие_2);
```

Сложные логические ветвления создаются путем объединения множества условий операторами `AND` (Логическое И) или `OR` (Логическое ИЛИ). Например: `(Wheels >= 4 AND doors <= 2)`.

## 🟢 ЧАСТЬ 1: РАБОТА С ЧИСЛОВЫМИ ДАННЫМИ (INT, FLOAT)

Ниже представлены основные операторы СУБД для фильтрации числовых значений:

| Operator | Condition | SQL Example |
| :--- | :--- | :--- |
| `=`, `!=` (или `<>`), `<`, `<=`, `>`, `>=` | Стандартные операторы сравнения | `Wheels != 4` |
| `BETWEEN ... AND ...` | Вхождение числа в закрытый диапазон (включая границы) | `Wheels BETWEEN 1 AND 4` |
| `NOT BETWEEN ... AND ...` | Число не входит в указанный диапазон | `Wheels NOT BETWEEN 1 AND 3` |
| `IN (...)` | Число соответствует одному из значений в списке | `Wheels IN (2, 4)` |
| `NOT IN (...)` | Число отсутствует в заданном списке | `Wheels NOT IN (1, 3, 5)` |

> **💡 На заметку пентестеру:** Грамотное написание условий `WHERE` не только делает данные читаемыми, но и критически ускоряет выполнение запроса на стороне СУБД, снижая нагрузку на процессор и минимизируя трафик между БД и бэкендом.

## 🟢 ЧАСТЬ 2: РАБОТА С ТЕКСТОВЫМИ ДАННЫМИ (STR / VARCHAR)

При формировании условий `WHERE` для столбцов, содержащих строки, SQL поддерживает специализированные операторы для гибкого сопоставления, поиска по маске и работы с шаблонами (символами подстановки / уайлдкардами).

| Operator | Condition | Example |
| :--- | :--- | :--- |
| `=` | Точное сравнение строк (в SQL используется **один** знак равенства) | `col_name = 'abc'` |
| `!=` или `<>` | Проверка строк на неравенство | `col_name != 'abcd'` |
| `LIKE` | Сравнение строк с использованием шаблонов маски | `col_name LIKE 'ABC%'` |
| `NOT LIKE` | Инверсия поиска по шаблону | `col_name NOT LIKE 'ABCD%'` |
| `%` | Маска: заменяет **любую последовательность из нуля или более символов** (используется только внутри `LIKE` / `NOT LIKE`) | `col_name LIKE '%AT%'` (найдет **AT**TIC, C**AT**, B**AT**S) |
| `_` | Маска: заменяет **строго один любой символ** | `col_name LIKE 'AN_'` (найдет **AN**D, **AN**T, но проигнорирует AN) |
| `IN (...)` | Строка полностью соответствует одному из текстовых значений в списке | `col_name IN ('A', 'B', 'C')` |
| `NOT IN (...)` | Строка отсутствует в заданном текстовом списке | `col_name NOT IN ('D', 'E', 'F')` |

> **⚠️ СУБД-Специфичный Варнинг:**
> Поведение оператора `LIKE` зависит от выбранного движка СУБД. В MySQL и SQLite `LIKE` по умолчанию нечувствителен к регистру (`case-insensitive`). В PostgreSQL `LIKE` строго чувствителен к регистру, а для поиска без учета регистра там используется оператор `ILIKE`.

### 🛠️ ЛАБОРАТОРНЫЙ КЕЙС №2: Текстовая фильтрация
Используя ту же самую таблицу **`table2`**, выполним ряд текстовых выборок по столбцам `title` и `director`.

#### 📋 Задачи для самопроверки (Строки):
1. Найти все части франшизы "История Игрушек" (Toy Story).
2. Найти все картины, режиссером которых выступил Джон Лассетер (John Lasseter) двумя путями.
3. Найти все фильмы и их режиссеров, которые были сняты кем угодно, но **не** Джоном Лассетером.
4. Найти все мультфильмы, название которых начинается на "WALL-" и заканчивается строго на один символ подстановки.

#### ✅ РЕШЕНИЯ (Строки):

1️⃣ Поиск по маске `%` (названия, начинающиеся на Toy Story):
```sql
SELECT * FROM table2 WHERE title LIKE 'Toy Story%';
```

2️⃣ Вариант 2.1 (Точное совпадение через `=`):
```sql
SELECT title FROM table2 WHERE director = 'John Lasseter';
```

3️⃣ Вариант 2.2 (Сопоставление через `LIKE`):
```sql
SELECT title FROM table2 WHERE director LIKE 'John Lasseter';
```

4️⃣ Вариант 3.1 (Исключение режиссера через `NOT LIKE`):
```sql
SELECT title, director FROM table2 WHERE director NOT LIKE 'John Lasseter';
```

5️⃣ Вариант 3.2 (Исключение через оператор неравенства `!=`):
```sql
SELECT title, director FROM table2 WHERE director != 'John Lasseter';
```

6️⃣ Поиск по строгому одиночному уайлдкарду `_`:
```sql
SELECT title FROM table2 WHERE title LIKE 'WALL-_';
```
